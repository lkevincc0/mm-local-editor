\section{Project Overview}

AMMBER is a web-based motivational modelling tool used in teaching and research for roughly fifteen years. We are extending the existing React/TypeScript editor (fork: \href{https://github.com/lkevincc0/mm-local-editor}{github.com/lkevincc0/mm-local-editor}) so that lecturers and reviewers can give structured feedback on motivational models, and so that models can be shared as portable files. In Week 3, the client confirmed that neither a cloud service nor a shared database was required. The team therefore removed the backend from scope and adopted local browser storage.

Delivered in Weeks 1--6 (implementation evidence below; the develop branch is continuously deployed to \href{https://lkevincc0.github.io/mm-local-editor/}{GitHub Pages}):

\begin{itemize}
  \item \textbf{Local project workspace} - create/open/rename/delete projects persisted in-browser, no server (PR \href{https://github.com/lkevincc0/mm-local-editor/pull/3}{\#3}).
  \item \textbf{Unified editorial theme \& dockable canvas editor} - consistent visual identity; canvas fits and centres the model on load (PRs \href{https://github.com/lkevincc0/mm-local-editor/pull/3}{\#3}, \href{https://github.com/lkevincc0/mm-local-editor/pull/4}{\#4}).
  \item \textbf{Feedback feature end-to-end} - closable draw.io-style side panel, node-bound comments with click-to-locate, authoring, nested replies, editable profile header, generated avatars (PRs \href{https://github.com/lkevincc0/mm-local-editor/pull/5}{\#5}, \href{https://github.com/lkevincc0/mm-local-editor/pull/6}{\#6}, \href{https://github.com/lkevincc0/mm-local-editor/pull/9}{\#9}, \href{https://github.com/lkevincc0/mm-local-editor/pull/11}{\#11}, \href{https://github.com/lkevincc0/mm-local-editor/pull/19}{\#19}).
  \item \textbf{Image-only project import/export} - project JSON (name + feedback) embedded invisibly into exported PNG/SVG, so one image is a full portable backup (PR \href{https://github.com/lkevincc0/mm-local-editor/pull/7}{\#7}); compact share links via deflate compression (PR \href{https://github.com/lkevincc0/mm-local-editor/pull/20}{\#20}).
  \item \textbf{QR-code project sharing} - modernised share dialog inside the editor (PR \href{https://github.com/lkevincc0/mm-local-editor/pull/15}{\#15}).
  \item \textbf{Deployment \& robustness} - adaptive router basename, GitHub Pages asset paths, deploy permissions (PRs \href{https://github.com/lkevincc0/mm-local-editor/pull/2}{\#2}, \href{https://github.com/lkevincc0/mm-local-editor/pull/12}{\#12}, \href{https://github.com/lkevincc0/mm-local-editor/pull/13}{\#13}).
  \item \textbf{Quality pipeline} -- 20 Vitest unit/component test files and one Cypress E2E specification, all run by GitHub Actions; four reported issues fixed with regression coverage (PRs \href{https://github.com/lkevincc0/mm-local-editor/pull/14}{\#14}, \href{https://github.com/lkevincc0/mm-local-editor/pull/17}{\#17}, \href{https://github.com/lkevincc0/mm-local-editor/pull/18}{\#18}, \href{https://github.com/lkevincc0/mm-local-editor/pull/23}{\#23}).
\end{itemize}

\subsection{Frontend and Architectural Design}

The interface uses a warm, minimal editorial theme (warm paper \#f7f6f0, deep purple \#25213e and accent \#6b51c9). The feedback interface is a closable side panel so reviewers remain on the canvas; selecting a comment locates its model element. The dockable canvas workspace was introduced in \href{https://github.com/lkevincc0/mm-local-editor/pull/3}{PR \#3}, the feedback panel and node binding in PRs \href{https://github.com/lkevincc0/mm-local-editor/pull/5}{\#5} and \href{https://github.com/lkevincc0/mm-local-editor/pull/6}{\#6}, and image-based project portability in \href{https://github.com/lkevincc0/mm-local-editor/pull/7}{PR \#7}.

The application follows the local-first decision recorded in the \href{https://student-team-zvzgb5e3.atlassian.net/wiki/spaces/~7120206e0163ea5d37428b992775145124d7e8/pages/557378}{decision log} and \href{https://student-team-zvzgb5e3.atlassian.net/browse/KAN-18}{KAN-18}. It is a React 18/TypeScript/Vite single-page application: maxGraph provides the canvas, Redux Toolkit manages model state, and the \href{https://github.com/lkevincc0/mm-local-editor/blob/develop/src/components/context/ProjectProvider.tsx}{project provider} coordinates project data and feedback persistence. React Router uses an \href{https://github.com/lkevincc0/mm-local-editor/blob/develop/src/components/utils/basename.ts}{adaptive basename} so the same build works locally and under the GitHub Pages sub-path. Project data, feedback and profile settings remain in browser storage, while \href{https://github.com/lkevincc0/mm-local-editor/blob/develop/src/components/utils/imageMetadata.ts}{image metadata utilities} embed portable project data in PNG/SVG files. No backend or shared database is required.
